## 아직 확인하지 않은 것

코드와 가짜 서비스 시험은 있지만 실서비스에서 확인하지 않았거나, 사람이 확인해야 하는 항목이다. 괄호 안은 확인할 주체다.

### 3. 리뷰와 병합

- (에이전트) 필수 체크가 실패한 PR, 승인 뒤 헤드가 바뀐 PR, 비공개 저장소의 실행 경로. 공개 시험 저장소에서는 Checks 읽기 권한 없이도 체크가 읽혔는데, 그 원인과 비공개 저장소에서 403으로 멈추는지도 포함한다.
- (에이전트) GitHub의 403 응답을 권한 부족과 요율 제한으로 구분하는 동작. 문서와 가짜 응답으로만 시험했다.
- (에이전트) 리뷰어가 결함 있는 변경을 실제로 막는 비율. 측정한 적이 없다.

### 4. 포털과 인증

- (사람) 포털의 승인과 수정 요청. 운영자 본인 계정으로 PR에 리뷰를 남기는 흐름(`public_repo` 범위 요청 포함)과, 조직이 OAuth App 접근을 제한할 때의 실패 모양.
- (사람) GitHub OAuth App이 `code_verifier`를 받아 PKCE를 검증하는지, Safari와 모바일 브라우저에서 `__Host-` 쿠키로 로그인이 유지되는지.
- (에이전트) 실행 목록 조회의 성능. `runs` 표에 `(repo, created_at)` 인덱스가 없어 저장소의 행을 훑는다. 실행이 14건인 현재는 측정할 규모가 아니다.
- (에이전트) 중지 요청과 병합이 거의 동시에 일어날 때의 순서. Durable Object가 저장소 작업 중에 새 이벤트를 받지 않는 성질에 기대며, 실제 Workers 런타임에서 경합을 만들어 본 적은 없다.

### 5. 예산과 전환

- (사람) 추정 지출과 공급사 콘솔의 실제 청구액의 차이, 그리고 API 호출이 구독 크레딧에서 차감되는지.
- (사람) 포털의 한도 변경 폼. 운영자로 로그인해 저장하는 동작은 시험으로만 확인했다.
- (에이전트) 두 실행이 동시에 시작할 때 예약 확인이 서로를 보지 못하는 경우. 초과분은 출구 핸들러의 상한 확인이 제한한다.
- (에이전트) 핀 고정한 Claude Code 2.1.318이 실제로 보내는 `anthropic-beta` 값과 `tools` 배열의 형식. 요청 본문을 기록하지 않으므로 허용 목록이 실제 요청과 맞는지는 실행이 성공한다는 사실로만 안다.

### 7. 샌드박스 공개

- (에이전트) 인젝션 시험, 계정별 및 전체 쿼터, 전체 중지, 컨테이너의 비루트 실행.
- (에이전트) DNS 유출 실험의 재실행. 결과가 플랫폼 동작에 의존하므로 공개 직전과 샌드박스 관련 버전을 올릴 때 다시 한다.
- (사람) 악용 신고와 신규 계정 제한, 공개 자동 실행이 GitHub과 모델 공급사 정책에 맞는지, 그리고 공개 승인.
